# Лабораторная №10–11 — Saldo (Zen-Money)

Полноценное приложение учёта личных финансов: клиент на HTML/CSS/JavaScript и собственный REST API на Express с базой SQLite. Исходный интерфейс лабораторной №8 сохранён и расширен: можно добавлять, редактировать и удалять операции, создавать категории, фильтровать список по типу, категории и диапазону дат.

## Запуск

Нужен Node.js 20+ и Python 3 (для раздачи статических файлов). В **первом** терминале:

```bash
cd task10-11/server
npm install
npm start
```

Сервер доступен по адресу `http://localhost:3001`. В **другом** терминале:

```bash
cd task10-11/client
python -m http.server 8000
```

В Windows вместо `python` при необходимости используйте `py`. Откройте `http://localhost:8000/`. Нельзя просто открыть `index.html` через `file://`, поскольку клиент использует ES-модули. Сначала запускайте сервер, затем клиент.

## API

| Метод | URL | Действие |
| --- | --- | --- |
| GET | `/categories` | Получение категорий |
| POST | `/categories` | Новая категория (`name`, `type`) |
| GET | `/transactions` | Все операции; фильтры `category_id`, `type`, `from`, `to` |
| POST | `/transactions` | Новая операция |
| PUT | `/transactions/:id` | Обновление операции |
| DELETE | `/transactions/:id` | Удаление операции |

Пример данных для POST/PUT `/transactions`:

```json
{
  "amount": 25.5,
  "category_id": 1,
  "date": "2026-11-21",
  "comment": "Продукты"
}
```

`type` операции определяется по категории (его также можно передать, но сервер проверит совпадение). Ответ GET содержит `type` и `category_name` благодаря `JOIN` с таблицей `categories`. Параметры фильтров превращаются в параметризованные SQL-условия `WHERE`; фильтрации операций массивом на клиенте нет. Даты включают обе границы диапазона.

## Проверка API и журнал для сдачи

Запустите сервер, затем **в третьем терминале** выполните:

```bash
cd task10-11/server
npm run check
```

Скрипт `check-api.js` отправит настоящие HTTP-запросы на сервер: GET и POST для категорий, GET (с фильтрами), POST, PUT и DELETE для операций. Также проверяются ошибки `400` и `404`. Успешная проверка заканчивается строкой `УСПЕШНО: все шесть маршрутов и проверки 400/404 прошли.`

Чтобы приложить реальный лог к сдаче, запишите вывод:

```bash
node check-api.js > api-test-log.txt 2>&1
```

Это создаёт `server/api-test-log.txt` с результатами на вашей машине. Тест добавляет одну категорию с названием `Тест ...` и временно создаёт операцию, которую затем удаляет. **Проверьте, что сервер уже запущен.**

## Данные и хранение

При первом запуске `db.js` автоматически создаёт `server/database.sqlite` с таблицами `categories` и `transactions`. В пустую базу однократно импортируются 8 категорий и 10 демонстрационных операций из `server/seed.json` (содержимое исходной лабораторной №8). Далее все изменения сохраняются только в SQLite. Для полного сброса демонстрационных данных остановите сервер и удалите `server/database.sqlite`.

В `localStorage` сохраняются **только значения фильтров** (`saldo.filters`). Денежные операции и категории там не хранятся. Статистика на странице показывает доходы, расходы и баланс **по текущему результату серверных фильтров**.

## Структура

- `server/server.js` — Express, глобальные `cors()` и `express.json()`, подключение маршрутов.
- `server/db.js` — подключение к SQLite, создание таблиц, начальные данные.
- `server/validation.js` — проверка категорий, операций и параметров фильтрации.
- `server/routes/categories.js` — GET/POST категорий.
- `server/routes/transactions.js` — GET/POST/PUT/DELETE операций, `JOIN` и SQL-фильтрация.
- `server/check-api.js` — HTTP-проверка маршрутов с ожидаемыми статусами.
- `client/api.js` — `fetch`, `async/await`, обработка ошибок API.
- `client/ui.js` — DOM-отрисовка операций, статистики, категорий и фильтров.
- `client/main.js` — состояние интерфейса, события форм, вызовы API.
- `client/index.html`, `client/style.css` — интерфейс Saldo.

## Деплой

Локальная связка работает при запуске двух процессов. Для публичного доступа сервер Express нужно разместить на Node.js-хостинге с **постоянным диском для SQLite**, а статику клиента — на статическом хостинге; затем заменить `API_URL` в `client/api.js` на публичный HTTPS-адрес бэкенда. Публичный деплой не включён в архив, поскольку для него требуется аккаунт и сервер с постоянным хранилищем. Один лишь GitHub Pages не может запускать Node.js/SQLite.
