# Лабораторная №5 — что обязательно знать на защите

## 1. Суть игры Simon

Есть **четыре цветные кнопки** с индексами `0, 1, 2, 3` (зелёная, красная, жёлтая, синяя). После нажатия «Старт» компьютер генерирует один случайный цвет и показывает его подсветкой примерно на **480 мс**, затем делает паузу **230 мс**. Игрок повторяет этот цвет. Если ответ правильный, через короткую паузу добавляется ещё один цвет, и компьютер показывает **всю накопленную последовательность с начала**. Ошибка на любом элементе завершает игру; указаны достигнутый уровень и число успешно пройденных раундов.

**Пример:** уровень 1 — `[0]` → игрок нажал `[0]` → уровень 2 — `[0, 2]` → игрок нажимает сначала `0`, затем `2`. Если на втором уровне нажать `0`, затем `1`, наступит проигрыш. **Достигнут уровень 2, успешно пройден 1 раунд**.

## 2. Файлы и архитектура по слоям

- `index.html` — четыре кнопки с `data-pad="0"…"3"`, «Старт», уровень, сообщения, переключатель звука.
- `style.css` — сетка 2×2, подсветка `.is-lit`, анимация нажатия `.is-tapped`, адаптивная раскладка.
- `model.mjs` — **модель**: хранит правила; создаёт состояние, добавляет цвет, проверяет ввод. Не зависит от браузерных таймеров или DOM.
- `view.mjs` — **представление**: показывает фазу, уровень, статус, включает/отключает игровые кнопки, ставит CSS-классы подсветки.
- `script.js` — **контроллер**: обрабатывает события, выстраивает последовательную очередь через `setTimeout`, отменяет таймеры при перезапуске.
- `sound.mjs` — необязательный изолированный аудиослой на Web Audio API. Ошибка звука не должна прерывать игру.
- `model.test.mjs` — модульные проверки правил игры без браузера.

**Зачем слои?** `model.mjs` можно тестировать в Node.js; `view.mjs` можно оформлять независимо; асинхронные задержки централизованы в контроллере и не засоряют логику проверки.

## 3. Состояние игры и конечный автомат

`createGame()` возвращает объект `{ sequence: [], cursor: 0, phase: 'idle' }`.

- `sequence` — массив индексов цветов, например `[0, 3, 2]`. Его **не заменяют** одной последней цифрой; каждый новый раунд добавляет ровно один элемент.
- `cursor` — позиция **следующего ожидаемого нажатия** игрока, отсчитывается с нуля.
- `phase` — текущая фаза:
  - `idle` — игра ещё не началась;
  - `showing` — компьютер показывает комбинацию;
  - `input` — разрешён ввод игрока;
  - `transition` — игрок правильно ввёл всю последовательность, ожидается следующий раунд;
  - `lost` — введён неправильный цвет, игра окончена.

Типичный цикл: `idle → showing → input → transition → showing → input ...`. При ошибке: `input → lost`. Кнопка «Начать заново» из **любой** фазы сбрасывает всё и переводит в `showing` первого раунда.

**Почему фазу хранят в JS, а не определяют по CSS?** CSS-класс — это лишь визуальное представление. Модель должна однозначно знать, принимает ли игра ввод; иначе возможны клики в моменты анимации и расхождение данных с экраном.

## 4. Важнейшие функции

**`nextRound(game)`** выбирает `Math.floor(Math.random() * 4)` (индекс от 0 до 3), создаёт новый массив `[...game.sequence, color]`, ставит `cursor = 0` и `phase = 'showing'`. Таким образом каждый новый раунд удлиняет последовательность на один элемент и сохраняет её прежний префикс.

**`playSequence(position, ticket)`** — рекурсивный проигрыватель. Для очередного индекса он включает подсветку `lightPad(color, true)`, через `setTimeout` выключает её, ещё через `setTimeout` вызывает себя для следующего элемента. Когда элементы закончились, `beginInput()` переводит фазу из `showing` в `input`. Рекурсия **асинхронная**: каждое продолжение поставлено в очередь событий, поэтому переполнения стека от длины комбинации не происходит.

**`enterColor(game, color)`** сравнивает нажатый индекс с `sequence[cursor]`. Если фаза не `input`, возвращает `ignored`. Если цвет неверный — `lost`. Если цвет верный, но есть следующие элементы — увеличивает `cursor` и возвращает `continue`. Если угадана **вся** последовательность — возвращает `complete` и устанавливает `transition`.

**`cancelPending()`** выполняет три действия: увеличивает счётчик `generation`, отменяет все ID из `timers` через `clearTimeout()` и очищает подсветку. Поэтому повторный запуск не оставляет старых анимаций. Кроме физической отмены, проверка `ticket !== generation` защищает от устаревших продолжений последовательности.

**`startGame()`** вызывает отмену таймеров, создаёт пустое состояние и запускает первый раунд. Всё работает без перезагрузки страницы.

## 5. Почему здесь нужен `setTimeout`, а не `setInterval`

`setTimeout(callback, delay)` **однократно** выполняет функцию через заданное время. В `playSequence()` после завершения одной подсветки планируется следующая — возникает последовательная очередь действий. `setInterval` многократно повторял бы обработчик до явного `clearInterval`, что легко приводит к наложению интервалов после нескольких перезапусков. В проекте нет постоянно работающего интервала: каждый timeout сохраняется в `Set`, удаляется из него при срабатывании и очищается при сбросе.

Это напрямую выполняет требование PDF: **никаких «зависших» таймеров и проигрывания старых последовательностей после нового запуска**.

## 6. Понятия JavaScript, которые обязательно объяснить

- **Массив**: `sequence` содержит порядок цветов. Индекс — число от 0 до 3, а не название CSS-класса.
- **`Math.random()` / `Math.floor()`**: генерация случайного индекса кнопки.
- **Spread `...`**: `[...game.sequence, color]` создаёт новый массив и дописывает ровно один шаг; старая комбинация сохраняется.
- **`setTimeout` / `clearTimeout`**: отложенный вызов и отмена запланированной работы.
- **`Set`**: хранит уникальные идентификаторы активных таймеров. `timers.forEach(clearTimeout)` отменяет все, `timers.clear()` очищает реестр.
- **Замыкание**: функция, переданная в `setTimeout`, помнит `position`, `color` и `ticket` из внешней области видимости.
- **Event loop**: JavaScript не «спит» во время задержки; браузер выполняет callback позже, когда наступает его очередь.
- **`addEventListener('click', ...)`**: запускает обработчик по нажатию; на `board` используется **делегирование событий** — один обработчик для четырёх кнопок, индекс берётся из `dataset.pad`.
- **CSS-классы**: `classList.toggle('is-lit', true/false)` меняет только подсветку, но не фазу игры.
- **`disabled`**: во время `showing`, `transition`, `idle`, `lost` кнопки недоступны; проверка `game.phase !== 'input'` в контроллере дополнительно игнорирует некорректные клики.
- **Web Audio API (бонус)**: осциллятор генерирует короткий тон, который не привязан к логике переходов; пользователь включает звук чекбоксом.

## 7. Вопросы преподавателя и короткие ответы

**Почему при верном раунде показывается старая последовательность, а не только новый цвет?** Таковы правила Simon: `nextRound()` дополняет сохранённый массив, а `playSequence(0, ...)` всегда начинает с нулевого индекса.

**Что запрещает клик во время показа?** И `disabled` у кнопок, и проверка `phase === 'input'` в контроллере и модели. Подсветка не означает, что ввод разрешён.

**Как определяется победа в раунде?** Последний верный клик наступает при `cursor === sequence.length - 1`. Только тогда возвращается `complete`, а не после одного верного нажатия.

**Почему после ошибки не продолжают работать старые таймеры?** Контроллер вызывает `cancelPending()`; он делает `clearTimeout` для всех зарегистрированных ID и меняет `generation`. Каждый следующий callback проверяет, относится ли он к актуальному поколению игры.

**Чем «достигнутый уровень» отличается от числа пройденных?** Если ошиблись на уровне N, попытка уровня N состоялась, но успешно завершено только N−1 раундов. Оба числа явно показаны в интерфейсе.

**Почему нет Canvas?** По заданию необходимы обычные DOM-кнопки и управление CSS-подсветкой; Canvas не нужен.

## 8. Демонстрация перед сдачей

1. Нажать «Старт»: загорается один цвет; во время подсветки цветные кнопки недоступны.
2. Повторить один цвет: через паузу покажется комбинация из **двух** цветов, начиная с первого.
3. Повторить правильную последовательность: появится уровень 3 с комбинацией из трёх цветов.
4. Ошибиться на следующем уровне: выводится «Игра окончена. Вы дошли до уровня N», цветные кнопки блокируются.
5. Нажать «Начать заново» несколько раз **во время показа**: новая игра всегда начинается с уровня 1; старая очередь не продолжает выполнение.
6. По желанию включить «Звук» и убедиться, что игра работает и при выключенном звуке.
7. Посмотреть DevTools → Console: при повторных запусках и ошибках не должно быть исключений.

**Тестирование из корня репозитория:** `node --test task5/model.test.mjs`. Локально: `python3 -m http.server 8000` и адрес `http://localhost:8000/task5/`. Страница также работает через GitHub Pages. Не открывайте страницу как `file://`, так как импорт ES-модулей часто блокируется без HTTP.
